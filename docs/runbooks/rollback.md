# Rollback Runbook

## 目标

当发布后出现功能回归、安全问题或环境异常时，能够快速回退到明确版本，而不是临场决定怎么救火。

---

## 触发条件

- 关键路径功能失效
- 安全风险提升
- 数据兼容性问题
- 性能严重退化

---

## 回滚前确认

1. 问题是否已稳定复现
2. 是否存在更小范围的热修复方案
3. 当前可回滚目标版本 / tag 是什么
4. 是否会影响数据格式或状态兼容性

---

## 标准回滚动作

### 代码回滚

优先策略：

1. 回滚到上一个稳定 tag
2. 或对问题 PR 执行可审计的 `git revert`

### 流程回滚

- 记录回滚原因
- 记录回滚提交或 tag
- 记录回滚执行人和时间

---

## 回滚后动作

1. 验证服务是否恢复
2. 新建 bug 或 security issue
3. 更新 `docs/product/current-state.md` 中的当前风险
4. 如果 runbook 失效，立即修正文档
