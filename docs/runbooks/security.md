# Security Runbook

## 目标

为这个高风险仓库定义默认安全边界，让 Agent 和人都知道：

- 默认能做什么
- 默认不能做什么
- 改高风险区域时必须补什么文档与验证

---

## 默认权限模型

| 角色 | 默认允许 | 默认禁止 |
|---|---|---|
| Agent | 建分支、改文件、跑本地验证、提交、推送分支、准备 PR | 直连生产、使用生产密钥、合并受保护分支、绕过审查 |
| Reviewer | 审查 PR、要求补文档、要求补测试 | 代表发布操作员执行生产发布 |
| Maintainer | 合并 PR、维护默认分支与模板 | 默认不应让 Agent 共享生产权限 |
| Release Operator | 发布、回滚、环境级操作 | 在无审计记录时直接变更生产 |

---

## 敏感区域

以下目录默认为高风险区域：

- `web/`
- `tools/`
- `remote_executor/`
- `internal_network/`
- `app/tool_framework.py`
- `app/ctf_agent_graph.py`

修改这些区域时必须：

1. 说明风险影响面
2. 说明新增或改变的能力边界
3. 说明验证命令
4. 同步更新相关 runbook / spec

---

## 默认禁止项

- 不要把秘密、凭据、私钥提交到仓库
- 不要让 Agent 直接操作生产环境
- 不要在未说明理由的情况下扩大命令执行边界
- 不要在未说明理由的情况下关闭 TLS / SSH 校验
- 不要把安全策略只写在聊天记录里

---

## 安全检查入口

统一使用：

```bash
make security
```

如果扫描器或依赖缺失，优先修正环境和 runbook，而不是把扫描器静默跳过。
