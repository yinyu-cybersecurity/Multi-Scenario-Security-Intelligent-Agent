# 0001 - Repo Factory Mode

## Status

Accepted

## Context

仓库过去更接近“高能力工作区”：

- 规划可能散落在聊天记录和临时说明里
- 任务边界不总是显式
- 机器接手时需要先猜意图，再猜文档，再猜命令

这会导致：

- 交接成本高
- 审查困难
- 自动化不稳定
- 权限和流程容易越界

## Decision

从现在开始，仓库采用“工厂模式”协作骨架：

1. `AGENTS.md` 只保留总控原则和文档导航。
2. 具体、可执行、可维护的内容全部落到 `docs/`。
3. 需求契约放到 `specs/`。
4. 常见操作通过 `Makefile` 提供统一入口。
5. Agent 默认权限限制在分支、提交、测试、推送、PR 范围内。

## Consequences

正面影响：

- 机器接手成本下降
- 审查路径更明确
- 仓库内的“事实来源”更稳定

代价：

- 文档维护工作会增加
- 不符合 spec / runbook 的改动会被拒绝或要求先补文档

## Follow-up

- 把 CI 逐步迁移到 `Makefile`
- 为高风险目录补充更细的技术决策记录
- 逐步吸收旧的散装文档
